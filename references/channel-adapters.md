# 插件式渠道注册（加渠道、写适配器）

> **什么时候读**：要新加一个渠道、改某个渠道的取数开关、或写新适配器的时候。合规能不能采先看 `redlines.md`；采集动作细节看 `collection-playbook.md`；这里只讲「渠道怎么登记进系统」。

一句话：**加渠道，90% 情况只改 `channels.yaml` 一处。** 这是专门补同类采集脚本「加一个渠道要改 4 处」的短板。

## 一、唯一配置 channels.yaml

全 skill 的渠道清单、开关、取数参数，**只有这一份文件**。示例见 `examples/channels.example.yaml`。

四块结构：

| 块 | 装什么 |
|---|---|
| `version` | 配置版本号 |
| `defaults` | 所有渠道共用的默认参数（限流、分页、告警等） |
| `channels[]` | 一个渠道一段，逐条列开启 / 关闭、取数入口、字段映射、合规声明 |
| `slices[]` | 切片定义（先定 slice 再聚类，见 `analysis-playbook.md`） |

## 二、配置字段表

### `defaults`（全局默认）

| 字段 | 大白话 |
|---|---|
| `rate_limit_qps` | 每秒最多发几个请求，频率克制 |
| `random_jitter` | 两次请求之间加随机抖动，别踩着整点打 |
| `max_pages` | 最多翻几页，防止失控 |
| `page_size` | 每页条数，**≤100** |
| `retry_on` | 哪些情况才重试（只 5xx / 429，见 `redlines.md`） |
| `snapshot` | 是否存原始响应快照（证据链） |
| `redact_pii` | 是否脱敏（默认开，见 `env-and-risks.md`） |
| `enabled_default` | 新渠道默认是关是开，**默认最严 = 关** |
| `empty_result_is_alert` | 空结果是否告警，**默认要告警** |

### `channels[]`（每个渠道一段）

| 字段 | 大白话 |
|---|---|
| `key` | 渠道代号，落库用 `channel_key` |
| `name` | 展示名 |
| `enabled` | 开 / 关 |
| `mode` | 取数方式（对应下面 3 种适配器之一） |
| `adapter` | 适配器名字，动态加载靠它 |
| `entry` | 取数入口（接口地址 / 页面 / 投放目录） |
| `params` | 参数 + 字段映射点路径（第七节） |
| `metrics` | 要采哪些数值指标 |
| `reviews` | 评论怎么采、取哪些字段 |
| `compliance` | 合规声明（第九节） |

## 三、适配器 5 方法契约

`adapter`（适配器）大白话：把「某个平台怎么取数」翻译成统一格式的插件。每个适配器都要实现下面 5 个方法，签名一致，主流程只认这 5 个。

| 方法 | 干什么 | 必须满足 |
|---|---|---|
| `probe(cfg)` | 探测这个渠道有没有数 | 报告**网页四步法做到第几步**、有无数据、空结果原因（见 `collection-playbook.md`） |
| `fetch_metrics(cfg, day)` | 取数值指标 | 只读，按业务日期，原值不乘系数 |
| `fetch_reviews(cfg, cursor)` | 取评论 | 单页 **≤100**、游标分页、`review_id` 必填、**逐字原句** |
| `normalize(raw)` | 把原始返回翻译成统一字段 | **不乘系数、不换算、留原文**（格式见 `data-schema.md`） |
| `compliance(cfg)` | 合规自检 | **默认最严，未声明即禁用**（第九节） |

> `cursor`（游标）大白话：翻页时记录「上次读到哪」，下次从那儿接着读，不重不漏。

## 四、内置 3 个通用适配器

绝大多数渠道靠这 3 个就能覆盖，**不用写新代码**：

| 适配器 | 适用 | 说明 |
|---|---|---|
| `public_json_api` | 公开返回 JSON 的接口 | 如 {{CHANNEL_A}} 公开评论接口；只读、按 `params` 映射字段 |
| `public_html` | 公开网页 | 先走网页四步法找内嵌数据 / 公开接口，再取数 |
| `manual_import` | 人工投放 | 读 `data/inbox/` 里公开导出的文件，**必须带填写人**（见 `redlines.md`） |

## 五、动态加载机制

- `ur_adapters.py` **按 `adapter` 名字动态加载**，不写死导入、不设字典白名单。
- 因此加渠道不用回去改主流程的名单；只有**全新平台、3 个通用适配器都盖不住**时，才新增一个适配器文件。
- 新增适配器文件**不改** `ur_collect.py` / `ur_core.py` / `ur_report.py`。
- 硬禁用项在配置层直接拒绝启动（第九节 / `redlines.md`）。

## 六、加渠道 5 步

- [ ] **① 登记**：复制一段 `channels[]`，填 `key` / `name` / `mode` / `entry`。
- [ ] **② 先探不采**：先设 `enabled: false`，跑 `--probe-only`，看四步法探测报告（做到第几步、有没有数、空结果原因）。
- [ ] **③ 选适配器**：能靠 3 个通用适配器覆盖，就只调 `params` 里的字段映射；盖不住才新增一个适配器文件。
- [ ] **④ 填合规**：写 `compliance`，逐项确认「公开匿名 / 无需登录 / 无需 cookie / 符合 ToS」。
- [ ] **⑤ 小跑再放开**：改 `enabled: true`，先 `--max-pages 1` 小跑，检查 snapshots 与空结果告警都正常，再放开正式采。

> 起步永远是 `enabled: false` + `--probe-only`，别一上来就真采。

## 七、字段映射点路径

`params` 里用「点路径」告诉适配器：原始返回里的某个值藏在哪个位置。

- 写法：用点 `.` 一层层往下指，如 `author.playtime_at_review` 表示「返回体里的 `author` 下面的 `playtime_at_review`」。
- 用途：把平台五花八门的字段名，对到统一字段（如 `playtime_hours`），落库格式见 `data-schema.md`。
- [ ] 映射只做「取出来、对上名」，**不做换算、不乘系数、不改原句**（这是 `normalize` 的红线）。
- [ ] 取不到的字段留空、归「未指明」桶，不许猜一个值填上。
- [ ] 短词 / 数字前的字段名要核对，命中纪律见 `collection-playbook.md`。

## 八、与「改 4 处」老做法对照

| | 同类采集脚本 | 本 skill |
|---|---|---|
| 加一个渠道要动 | **4 处**：硬编码 `import` + 4 处字典白名单 | **1 处**：`channels.yaml` 加一段 `channels[]` |
| 白名单漏改的后果 | 静默不生效、还以为采到了 | 动态加载，不存在漏改名单 |
| 全新平台 | 要动主流程多处 | 只新增一个适配器文件，不动主流程 |
| 探测 | 无独立探测步 | `--probe-only` 先看四步法报告 |

## 九、compliance 默认最严

- [ ] **未声明 `compliance` 即禁用**：宁可关着，也不让说不清合规的渠道偷偷跑起来（对应 `enabled_default` 默认关）。
- [ ] 属 `redlines.md` 第三节「明确不做」或第四节「硬禁用」的入口，配置层直接拒绝启动，不是灰着可开。
- [ ] `manual_import` / 自有账号 / 自有 App 后台一律标 `manual_confirmed` 并带填写人。
