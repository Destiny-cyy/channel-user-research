> **什么时候读**：阶段 A 采数的时候，尤其是要判断「这个网页到底有没有数」「扫不到算不算没有」「今天缺的数要不要补、怎么补」的时候。合规能不能采，先读 `redlines.md`；加渠道的开关看 `channel-adapters.md`。

## 一、网页四步法

判断「一个网页 / 入口到底有没有数」，**按顺序走完下面四步，做到第几步要能说清楚**。血泪教训：只做第 1 步就误判过两家没数，白对着屏幕读了一个月。

| 步 | 做什么 | 大白话 |
|---|---|---|
| ① | 看页面渲染文字 | 打开页面，人眼能看到、能复制的那些字 |
| ② | 翻内嵌数据块 | 页面源码里藏着的结构化数据，认 `__INITIAL_STATE__` / `__NEXT_DATA__` / `__NUXT__` / `application/json` 这几类 |
| ③ | 找页面 JS 引用的公开接口 | 页面加载时调的那些「看一眼就返回数据」的公开地址 |
| ④ | 都没有才判死 | 前三步全落空，才允许下「没有可用数据」的结论 |

> **任何「网页没数 / 扫不到」的结论，必须写明做到第几步。**

**模板句（照抄填空即可）**：

> 渠道 `___` 判定「无可用数据」，网页四步法**做到第 `___` 步**：① 页面文字 `（有/无，取值 ___）`；② 内嵌数据块 `（查了哪几个、有无命中）`；③ 公开接口 `（找到/未找到，地址 ___）`；④ 结论 `（判死 / 需人工投放）`。空结果原因：`___`。

- [ ] 只做到第 1 步就判「没数」→ 视为无效结论，必须往下做。
- [ ] 探测报告由适配器的 `probe(cfg)` 产出，字段见 `channel-adapters.md`。

## 二、扫不到 ≠ 没有

「扫描 / 打包这个动作本身完整吗」永远先问这一句，再谈有没有数。

- [ ] **先确认扫描完整**：曾因为「按目录挑、静默跳过了超限的大目录」而误判没数；改成**按单文件挑**后，翻案找出了原本被跳过的内容。
- [ ] 检查有没有被静默跳过、超限截断、打包漏项；有就先修扫描，再重下结论。
- [ ] 结论里区分两种「没有」：*真的没有* vs *我没扫到*。后者不算结论。

## 三、动手前先看数据类型（int-str / protobuf）

决定「能不能扫出精确整数」，先花十秒看接口返回长什么样，别闷头扫。

| 情况 | 判断 | 怎么办 |
|---|---|---|
| 返回是**整数** | 有望拿到精确值 | 按原值入库 |
| 返回是**格式化字符串**，如「93.3万人已预约」 | 别指望扫出精确整数 | 原样存这句话，`precision` 按量级填，**不私自换算** |
| 返回是 **protobuf 二进制** | 字段名不随数据一起传，按文字 `grep` 必然 0 命中 | 别用文本搜索硬找；这类不上线，如实说明取不到 |

- 大白话：`int-str` 就是「先看清是数字还是一句话」；`protobuf` 是一种压缩的二进制格式，里面字段名不上线，用文本搜索搜不到。
- [ ] 是格式化字符串 / 二进制时，绝不当成「扫不到 = 没有」，也**绝不反推一个精确整数**。

## 四、命中纪律

扫一个数，要的是**唯一命中**，不是「落在大范围内就算」。

- [ ] **要唯一命中**，不接受「落在锚点区间内」这种模糊结果。
- [ ] 搜索范围限制在**标识附近 ±5000 字符**，别全篇乱扫。
- [ ] **短词必配全名校验**：只搜到「预约」两个字不算数，要连同游戏全名 / 完整标识一起核对。
- [ ] **看数字前面的字段名**：确认这个数确实是目标指标，不是旁边的别的数。
- [ ] **排除干扰项**：UUID、图片链接片段里的数字，一律不算命中。

## 五、对照实验，不看 --help 字面

- [ ] **判定靠对照实验**，不靠命令帮助文字（`--help`）怎么说。写着的和跑出来的经常不是一回事。
- [ ] 判「在不在榜」**只认条目自身的 `game_id` / `pkgName`**，不靠页面标题、不靠搜索结果里出现名字。

## 六、多路降级优先级

主路挂了要有兜底，**精度可以退，但不能断数**。按下面顺序降级：

| 顺序 | 路子 | 说明 |
|---|---|---|
| ① | 网页直连 | 最优先，走公开接口 / 公开页面 |
| ② | App 缓存直读 | 网页不行，读已缓存的公开数据 |
| ③ | 读屏兜底 | 实在没有结构化数据，才退到读屏幕上可见的文字 |
| ④ | 收尾重尝试 | 最后统一补一次（规则见第八节） |

- 退到更粗的精度时，**如实标注 `precision`**（量纲含义见 `data-schema.md`），不许把粗值伪装成精确值。
- 频率、请求头、重试的纪律（一天只真采一次、真实浏览器头、随机抖动、只重试 5xx/429）见 `redlines.md` 第 6 条，此处不重复。

## 七、正常缺数白名单

**故障缺数**和**常态缺数**必须分开。下面这些属于「正常缺数」，不是故障，别急着重试、别报错夸大：

- [ ] 没进榜
- [ ] 后台表当天尚未刷新
- [ ] 熔断中
- [ ] 模拟器不可用
- [ ] 待补录
- [ ] 人工补录
- [ ] 投放目录为空

> `熔断` 大白话：连续失败太多次，系统主动暂停一会儿，避免一直撞墙。

## 八、收尾重尝试六条边界

一轮采完，统一做**一次**收尾重尝试，六条边界缺一不可：

| # | 边界 | 说明 |
|---|---|---|
| 1 | 只补「非正常缺数」 | 正常缺数 / 熔断 / 人工未给 **一律不碰**（白名单见第七节） |
| 2 | 每渠道最多一次、不循环 | 补一次就停，绝不反复轮询 |
| 3 | 冷却 30s | 重试前等一下，别贴着上一请求打 |
| 4 | 只写回当期 | 由 `can_write_back(day)` 判定，**只写今天** |
| 5 | 仍失败如实保留 + 追加原因 | 补不到就保留原状态，写明为什么，不伪装 |
| 6 | 反爬纪律照旧 | 频率、只读、随机抖动等照 `redlines.md` 执行 |

- [ ] **判定按 `value + 理由白名单`，故意不按 `status`**：排名等独立维度不该被一个总状态硬套，所以看「值是否缺 + 理由是否在白名单」，不看 status 字段。

## 九、can_write_back 日期护栏

- `can_write_back(day)` 只放行**今天**：历史日期的自动流程不许回写，防止一次重试把过去某天的数覆盖掉。
- 自动采集、自动收尾重尝试都受这道护栏约束。
- 人工补采通道**不受它约束**，见第十节的作用域隔离。

## 十、缺口填补准则

某天真值确实缺了，允许**用邻近时点的真值平移填补**，但必须诚实：

- [ ] 填补值须**如实标注真实 `captured_at`**（写明这数其实是哪天采的），**禁止假装是当天当场采到的**。
- [ ] 这是「平移真值」，不是估算、不是插值、不是按趋势外推——**一个系数不乘**。
- [ ] 变化小于 `precision` 时写「—」，**绝不填 0**（见 `data-schema.md`）。

**人工 / 自动作用域隔离（重要）**：

| 通道 | 用途 | 是否受 `can_write_back` 约束 | 是否受自动护栏约束 |
|---|---|---|---|
| 自动流程 | 日常采集 + 收尾重尝试 | 是，只写今天 | 是 |
| 人工补采 `--day --force` | 人明确指定补某一天 | 否 | 否，与自动护栏作用域隔离 |

> 大白话：人是「我知道我在补哪天」才手动补的，所以不拦；但补进去照样要标真实采集时刻、照样不许伪装。

## 十一、证据链与人工补录

**任何一个数都要能回溯到出处。**

| 证据 | 位置 | 规则 |
|---|---|---|
| 原始响应副本 | `data/snapshots/<渠道>/<日期>/<hash>.json` | 只增不改；含请求参数、时间戳、HTTP 状态、脱敏后内容 + 哈希指纹 |
| 人工投放 | `data/inbox/` | 只读入库，**必须带填写人**（写进 `note`） |
| 审计轨迹 | `data/audit/append-only.jsonl` | append-only（只追加、不覆盖），谁 / 何时 / 确认了什么 |

- [ ] 人工投放文件丢进 `data/inbox/` 时，`note` 带填写人、`compliance_tag` 标 `manual_confirmed`（见 `redlines.md` 3.1）。
- [ ] 保留原始响应 JSON / 请求参数 / 时间戳，便于日后重跑复核。
- 脱敏与「原始副本不可变」之间的张力，见 `env-and-risks.md`。

## 十二、空结果告警模板

> 采不到会明说、绝不假装成功——这条的行为准则在 `redlines.md` 第五节，这里给可直接套用的告警格式。

```
[空结果告警]
渠道 / 入口：___
业务日期：___
采集时刻 captured_at：___
网页四步法做到第 ___ 步：① ___ ② ___ ③ ___ ④ ___
扫描完整性自检：通过 / 未通过（原因 ___）
返回类型：整数 / 格式化字符串 / protobuf 二进制 / 空
空结果原因：___（正常缺数白名单项 / 故障 / 需人工投放）
下一步动作：___（例：转人工投放 / 保持 skipped / 读屏兜底）
状态：failed / skipped（带理由），未填 0、未平移、未伪装成功
```

- [ ] 每条告警都要有「下一步动作」，不能只报「空的」就完事。
- [ ] 告警同时进入报告异常区（报告规矩见 `analysis-playbook.md`）。
