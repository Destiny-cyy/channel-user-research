## 一、一句话立场

**精度不够就不硬算，算不出来就如实说、明确告诉对方；绝不制造「看着挺精确、其实是估的」假象。** 原值入库一个系数都不乘，不做口径估算、推算、插值，口径不可比的数据不放在一起汇总。这条是本 skill 所有文档的头号原则，不是建议。

大白话解释几个会反复出现的词：

| 词 | 大白话 |
|---|---|
| 原值入库 | 采到多少写多少，「93.3 万人已预约」就原样存这句话，不私自换算成 933000 |
| 只读（GET/HEAD） | 只用「看一眼」的方式取数，绝不点会改动对方系统的按钮 |
| 原子写 | 先写临时文件、写完了整体替换，绝不写一半留个残文件 |
| 快照 | 把接口返回的原始内容原封不动存一份，日后能翻案复核 |
| 硬禁用 | 配置层直接拒绝启动，不是「灰着、你想开可以开」 |

## 二、10 条硬红线（白话版 + 违反后果）

这 10 条是从渠道采集实践里沉淀下来的通用纪律，违反任意一条立即停止整轮。

| # | 红线（白话） | 大白话解释 | 违反后果 |
|---|---|---|---|
| 1 | 不估算、不推算，原样入库 | 一个数没真采到，就空着，别拿昨天的数补、别按趋势猜 | 报告出现假精确，业务拿去投预算会投错；且再也说不清哪个数是真的 |
| 2 | 不抓包解密、不逆向、不绕加密 | 不去拆对方 App/网页的通信内容、不破解签名参数 | 触碰平台条款与法律边界，整轮作废，账号可能被封 |
| 3 | 采集全程只读，绝不点改变对方状态的按钮 | 原话是「绝不点预约按钮」，抽象成更通用的一句：只 GET/HEAD，不 POST、不点赞、不预约、不提交任何写操作 | 会真的改到对方系统的数据（比如虚增一个预约），既污染数据又越界 |
| 4 | 绝不登录他人账号 | 只用账号持有人本人自己登录的状态，别人的一律不碰 | 未授权访问，责任与后果由操作方承担，整轮作废 |
| 5 | 原子写 | 临时文件写完、校验过，再一次性替换正式文件 | 中途崩了留下半截文件，历史数据被污染且难恢复 |
| 6 | 一天只真采一次 + 真实浏览器头 + 随机抖动 + 失败只重试 5xx/429 | 别反复骚扰同一接口；请求头用正常浏览器的；两次请求间隔带随机；只有「服务器临时错 / 被限流」才重试，别的错（如 404、参数错）不重试 | 频率过高触发风控被封；对不该重试的错反复重试，等于放大故障 |
| 7 | 不走申请后台权限 + 手动导出 | 默认做法是「不去申请后台权限、不靠人工导出」 | 见第三节：本档在**自有 App 官方后台**这一限定场景下已显式放宽，其余场景仍照旧 |
| 8 | 不主动找对接运营 / 商务要数 | 不靠「找人要」来凑数据 | 见第三节：同样只在**自有 App 官方后台**场景放宽，其余场景「不主动找人要数」仍保留 |
| 9 | 只扫缓存、不碰账号聊天 | 只在公开数据 / 已缓存内容里找，不进私人聊天、私信、账号内容 | 碰到私人数据，越界且引入无法脱敏的信息 |
| 10 | 清理只移动归档、不删除 | 要下线旧数据只挪到归档目录，绝不 `rm` | 误删用户文件或历史证据，证据链断掉、无法复核 |

> 第 6 条里的 `5xx` 指「对方服务器自己出错」，`429` 指「对方说你请求太快了」，这两种才值得稍等重试；其它失败原因重试也没用，如实记下即可。

## 三、本档合规档位：自有账号 + 自有 App 官方接口

> 这一档是经反复澄清后**拍板定下**的：先选过「严格继承既有采集红线」，后改选「放宽」，最后澄清定为 **「自有账号 + 自有 App 官方接口」**。以下逐条照录，判定以此为准。

### 3.1 允许做什么

- [x] 用**自己 / 团队名下账号**的登录态。
- [x] 用**自有 App 的官方后台接口**取数，具体是：
  - {{OWNED_CHANNEL_BACKEND}} 的 `{{OWNED_REVIEW_METHOD_A}}`
  - {{OWNED_CHANNEL_API}} 的 `{{OWNED_REVIEW_METHOD_B}}`
  - 各商店**自有后台**的导出功能
- [x] 以上两类都必须标 `manual_confirmed`，且 `note` 里**带填写人**（谁放进来、谁确认的，写清楚）。

### 3.2 保留（仍然不许做）

- [ ] 不抓包解密
- [ ] 不逆向
- [ ] 不绕验证码 / 加密 / 风控
- [ ] 不破解签名参数
- [ ] **绝不登录他人账号**
- [ ] 不代理轮换规避封禁
- [ ] 不点任何会改变对方系统状态的写操作（**采集全程只读 GET/HEAD**）
- [ ] 不碰私人数据
- [ ] 频率克制
- [ ] 空结果告警
- [ ] 采不到明说、绝不伪装成功
- [ ] 原子写
- [ ] 只移动归档、不删除
- [ ] 原值入库

### 3.3 明确不做（不写成可选项、不列成「可申请开通」）

- [ ] 绕验证码
- [ ] 抓包解密
- [ ] 破解签名
- [ ] 登录态复用他人账号
- [ ] IP 轮换规避封禁

> 这五项是硬边界，不是「默认关、可以商量打开」的开关，任何配置都不得把它们变成可选项。

### 3.4 相对既有采集红线被显式放宽的两条（务必看限定场景）

| 原红线 | 原内容 | 本档怎么处理 |
|---|---|---|
| 红线 7 | 不走申请后台权限 + 手动导出 | 在**自有 App 官方后台**这一限定场景下不再适用 |
| 红线 8 | 不主动找对接运营 / 商务要数 | 在**自有 App 官方后台**这一限定场景下不再适用 |

- 关键限定词：**自有 App 官方后台**。只有这个场景放宽。
- 其余场景「不主动找人要数」**仍然保留**，不得顺势推广到别的渠道。

### 3.5 放宽变不出接口（必须写明白）

**放宽的是「能不能用自己账号 / 自家后台」，不是「凭空多出一个接口」。** 接口是平台给的，不是放宽出来的：

- {{CHANNEL_B}} / {{CHANNEL_C}} / 各应用商店**他人游戏**的评论，**没有官方接口**。
- 因此这些渠道**自动采集默认关**，只走**人工投放**：把公开导出的文件丢进 `data/inbox/`，并带填写人。
- 自有账号的操作，由**账号持有人本人**执行。
- **平台条款责任由使用方承担**——用自家账号、走自家后台，遵守哪些条款、能不能这么用，是账号所属团队自己的事。

> 一句话记法：*放宽 = 允许用「自己的」，不等于能拿「别人的」，更不等于能造接口。*

## 四、各渠道默认状态表

这张表是配置的默认值基准，具体开关落在 `channels.yaml`（见 `channel-adapters.md`）。

| 渠道入口 | 默认状态 | 说明 |
|---|---|---|
| {{CHANNEL_A}} 官方 `{{PUBLIC_REVIEW_ENDPOINT}}` | **启用** | 官方公开接口，按只读纪律采 |
| {{CHANNEL_D}} 公开 RSS | **启用，但强制运行时探测 + 空结果告警** | 2026 年有「返回空」争议，采前先探一次、空了要报，不能假装成功 |
| 自有 App 的 {{OWNED_CHANNEL_BACKEND}} / {{OWNED_CHANNEL_API}} | **启用**（标 `manual_confirmed`） | 属 3.1 允许范围，带填写人 |
| 自有 App 商店后台导出 | **启用**（标 `manual_confirmed`） | 属 3.1 允许范围，人工投放、带填写人 |
| {{CHANNEL_E}} 页面 / 第三方 private RPC 库 | **禁用** | 平台条款（ToS）禁止自动化，不碰 |
| {{CHANNEL_B}} / {{CHANNEL_C}} / 各应用商店**他人**评论 | **禁用，仅人工投放** | 无官方接口，自动采集默认关，走 `data/inbox/` |
| 任何需登录他人账号 / 验证码 / 加密 / 风控的入口 | **硬禁用** | 配置层直接拒绝启动，不是灰着可开 |

> `ToS` 大白话：平台的服务条款，写明了「不许用程序自动抓」就不能自动抓。

## 五、采不到会明说，绝不假装成功

这是本档最硬的一条行为准则，单独成节。

- [ ] **空结果一律告警**，并在告警里写明「网页四步法做到第几步」（四步法见 `collection-playbook.md`）。
- [ ] **「扫不到 ≠ 没有」**：报「没数」之前，先确认扫描 / 打包这个动作本身是完整的（曾因按目录挑、静默跳过超限目录而误判，改成按单文件挑后翻案）。
- [ ] 采不到就**实话说采不到**，把状态记成 `failed` / `skipped` 并带上理由，绝不填 0、绝不用邻近时点的值冒充当场采到。
- [ ] 若确需平移填补，**如实标注真实 `captured_at`**（细节见 `collection-playbook.md`）。
- [ ] 空结果告警模板在 `collection-playbook.md`；存疑数据隔离不入库的规则在 `data-schema.md`。

> 反例（绝对不许）：某渠道返回空 → 脚本不报错、写一行 `0` 或复制昨天的值 → 报告显得一切正常。这属于「伪装成功」，违反即停止。

## 六、三层落地

同一套红线，分三层写、彼此不多复制，改一处时对得上号：

| 层 | 落在哪 | 作用 |
|---|---|---|
| 铁律层 | `SKILL.md` 的「硬性规则」8 条 | 一句话速记，开工前扫一眼，违反即停止 |
| 原文层 | **本文件** `redlines.md` | 逐条摊开、能照着判定的完整版（10 条红线 + 本档放宽边界 + 默认状态表） |
| 脚本护栏层 | `scripts/ur_fetch.py`、`scripts/ur_core.py`、`scripts/ur_collect.py` | 把红线写成跑不掉的检查：只读请求与限流退避、原子写与精度不倒退、硬禁用项拒绝启动与空结果告警 |

- 配置层「硬禁用项拒绝启动」是护栏的第一道闸，见 `channel-adapters.md`。
- 环境与「明确不装」清单见 `env-and-risks.md`。
